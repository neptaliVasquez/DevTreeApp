[Catalog] [DIS] HDR UK syndication: fix sync failures and release to production

Background
Investigation on 14–15 Oct found three push bugs and one pull bug in DIS. All four are fixed in DIS PR #168 (merged 15 Oct, live on staging). Production still runs DIS v1.1.8-hdruk-only (24 Sep) and needs a release.

Done (DIS PR #168, proven on staging 15 Oct)
[x] 13 production datasets never created on HDR UK (same 13 since 24 Sep). Cause: DIS omitted the provenance section when no datasetTypes value mapped, and HDR UK's GWDM 2.0 translation rejects that. Fix: always send provenance, falling back to "Health and disease / Others". Proof: a staging test dataset with no data type was created on the HDR UK test site.
[x] Edits never reaching HDR UK. Cause: HDR UK only updates when the listing version changes, and ours was always 1.0.0. Fix: version patch = fingerprint of the published content. Proof: renaming the test dataset in the staging ADWB Catalog updated the same dataset on the HDR UK test site.
[x] Random "An unexpected error occurred while updating dataset" on the HDR UK test site. Cause: on cache expiry, every parallel harvester request fetched the whole GRIP catalogue at once and passed HDR UK's 30 s timeout. Fix: 15-minute cache shared across requests and worker processes. Proof: 24 parallel requests went from 10 failed or over 30 s to 24 OK in about 6 s; test-site runs since then are clean.
[x] Missing History entries (12 Oct) explained: HDR UK records nothing for a run where no dataset was created, updated or failed. Not a bug on our side.
[x] Pull: "Request access" links to HDR UK datasets returned 404. Fix: link by the Gateway's numeric dataset id. Verification below.
[x] Dev tool scripts/dev/hdruk-validate (replays records through HDR UK's schemas and translation); HDR UK docs updated.
