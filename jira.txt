Subject: Sage sync fix tested in DIS dev on 7 October: all checks passed

We tested the fix for the Sage datasets problem in the DIS dev environment today. All five checks passed. The Catalog side is tested next, in staging.

What we tested, what came back, and the result

The Sage study list responds.
Output: HTTP 200. In production this call has returned an error (500) every night since 1 October.
Result: passed.

Studies with no files are left out.
Output: 163 studies returned. Synapse lists 201 today and 38 have no files, so 163 is the expected number.
Result: passed.

The right studies are in and the empty ones are out.
Output: PAK1-5xFAD and DivCo_HS are in the list. AUSBB, TREATAD_BV2, iNeuron_shRNA_transcriptome and the "Nominated Targets for Agora" entries are not.
Result: passed.

A dataset that looked empty now has its files.
Output: 8 files returned for PAK1-5xFAD. With the old Synapse snapshot it had none, which is why it has no Request access button in production.
Result: passed.

DIS reads the newest Synapse snapshot by itself, and logs what it left out.
Output: the log shows Data metadata snapshot: syn11346063.88 and Omitted 38 studies with no files, with the 38 names.
Result: passed.

One problem found and fixed during testing

The first run returned 146 studies instead of 163. DIS was reusing a study list from September 2025 that ships with the code, for the first 24 hours after each deploy. We fixed that in the same branch and re-ran the test, which gave 163.

Not tested yet, because it needs staging

The Request access button appearing in the Catalog for PAK1-5xFAD and DivCo_HS after the nightly sync.
One real access request for a Sage dataset.
Not covered by this fix

Datasets with no data that are already in the Catalog are not removed automatically. Support needs to remove about 37 of them once the fix is live in production.
